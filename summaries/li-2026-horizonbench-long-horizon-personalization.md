# HorizonBench: Long-Horizon Personalization with Evolving Preferences

**arXiv:** 2604.17283
**Authors:** Li, Paranjape, Oktar, Ma, Zhou, Guan, Zhang, Park, Chen, Yang, Tsvetkov, Celikyilmaz
**Affiliations:** UW, Meta, OpenAI, Stanford
**Date:** April 2026 (preprint)

## Core Problem

AI companions interact with users over months, and user preferences change throughout these interactions. But when a user's preferences shift — for example, a user who initially preferred Socratic-style philosophical engagement who later shifts to preferring direct frameworks after becoming a CEO — models need to **track the current preference**, not just the originally stated one.

This paper defines **long-horizon personalization**: the task of identifying a user's current preference value from a conversation history in which stated preferences have been changed by subsequent life events.

## Key Gap: "Belief-Update Failure"

The authors identify two distinct failure modes in existing benchmarks:

1. **Retrieval failure** — the model never found the preference at all
2. **Belief-update failure** — the model retrieved the *original* value but failed to update it after the life event

Existing benchmarks cannot tell these apart. HorizonBench is designed to isolate **belief-update failure** specifically.

## The Benchmark (HorizonBench)

- **4,245 items** from **360 simulated users**
- Each user has a **6-month conversation history** (~4,300 turns, ~163K tokens average)
- Preferences are modeled using a **structured "mental state graph"** — a causal model where life events drive preference changes through typed dependency edges
- Each benchmark item is a **5-option multiple-choice question**: given a full conversation history, which assistant response best aligns with the user's *current* preferences?
- **Hard-negative distractors**: for evolved preferences, the pre-evolution value is injected as option A, ensuring models can't answer from surface cues alone
- Items are filtered through a **5-LLM consensus filter**: items are only included if all five validation models (GPT-4.1, Gemini-3-flash, o4-mini, Claude-haiku-4.5, Claude-opus-4.6) answer incorrectly — proving the full history is necessary

## Mental State Graph (Data Generator)

Instead of inferring mental state from real conversations (which is underdetermined), the generator **produces conversations from a structured mental state graph**:

- Preferences are linked by **typed dependency edges** (e.g., dietary preferences → restaurant choices → social outing plans)
- **Life events alter preference values**, with changes propagating through these edges
- Every change records the triggering event as **provenance**
- A preference evolves on day 45 but was only expressed on day 10 — it remains **stale** and becomes a candidate for "temporal recall" testing at its updated value
- Events are sampled conditionally on agent states to prevent unrealistic repetition
- Expression variants (explicit vs. implicit) are generated by rewriting only preference-expressing turns

## Dataset Statistics

- 57,390 conversations, 1.6M turns across 360 users
- 6-month timelines with 142–168 conversations per user
- Spanning 30 preference domains
- Produced by three frontier generators (Claude-sonnet-4.5, o3, Gemini-3-flash) — 120 users each
- 9% pass rate through strict 5-LLM consensus filter
- **59% evolved preferences, 41% static**

## Key Results (25 Frontier Models)

| Finding | Detail |
|---------|--------|
| Best model | Claude-opus-4.5: **52.8%** accuracy |
| Most models | Score at or **below 20% chance baseline** |
| 10 of 25 models | Score below chance (7 of 8 OpenAI, 3 Gemini) |
| Human baseline | 56–64% accuracy (moderate agreement) |
| Error pattern | When models err, **over a third select the user's originally stated value** — the belief-update failure |
| Consistency | Belief-update failure persists across context lengths, expression explicitness levels, and model families |

## Controlled Experimental Dimensions

1. **Evolution status** (evolved vs. static preferences) — tests retrieval vs. belief-update separately
2. **Expression explicitness** (explicit vs. implicit preference signals) — tests whether models can infer preferences from subtle cues
3. **Context length** (full history vs. truncated) — tests whether the failure is due to context limitations vs. belief-update mechanism

## Human-AI Error Comparison

- **Human disagreements** arise from genuine ambiguity among plausible current-preference interpretations
- **Model errors** anchor on outdated pre-evolution preferences (belief-update failure)
- The best model (52.8%) falls within human accuracy range, but the **sources of error differ fundamentally**

## Connection to Related Concepts

- **Belief updating / knowledge conflict** (Xu et al., 2024): models anchor on prior evidence even when newer context supersedes it
- **State-driven vs. trait-driven behavior** (Harry et al., 2026): most user behavior variance is state-driven, yet benchmarks model only fixed traits
- **Task-conditioned projection** (Srinivasan et al., 2604.20158): HorizonBench implicitly tests whether memory systems can project evolved state rather than retrieving stale preferences

## Consumer Harm Relevance

This benchmark has direct relevance to:

- **AI assistant personalization harms**: models that fail to track preference evolution provide outdated, inappropriate assistance over time
- **Long-term AI companion relationships**: users in sustained AI interactions (dating apps, therapy bots, mental health companions) may receive increasingly misaligned advice as their circumstances change
- **Regulatory implications**: models demonstrating persistent belief-update failure on sensitive preference domains (health, legal, financial) represent a systemic risk for long-term AI users
- **Theory of mind gap**: the inability to update beliefs about a user's evolving state after life events reveals a fundamental limitation in AI's capacity for genuine user understanding
